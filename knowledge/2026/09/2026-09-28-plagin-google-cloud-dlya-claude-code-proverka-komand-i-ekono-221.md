## Идея
Автор изучил плагин Google Cloud для агентных инструментов и проверил его в Claude Code. Плагин требует сверять синтаксис с `gcloud help` для конкретной команды, а не полагаться на память модели: в проверенном примере для Cloud Run актуальными оказались флаги `--min-instances` и `--max-instances`, но не `--min-scale` и `--max-scale`. Ограничение вывода команд `list` тоже оказалось полезным: выбор нужных полей сократил ответ по 52 сервисам с 281 918 до 7 963 байт. Правила плагина также требуют явного проекта и разрешения человека для потенциально опасных операций. Для поиска сведений плагин предусматривает официальный сервис документации и загрузку дополнительных навыков по мере необходимости.

## Вывод
Автор применил уже установленный плагин в Claude Code и на своих проверках показал, что сверка команд помогает избежать устаревших флагов, а сокращение вывода экономит контекст. Подключение сервера документации через MCP у него не завершилось, но резервный REST-запрос вернул ответ со ссылками на официальные документы. Практический вывод: перед действиями в облаке проверять синтаксис и фактический ответ инструментов, ограничивать объём данных и запрашивать подтверждение для рискованных изменений.
