## knowledge-v2:gpt-6-luna

## Коротко
Автор создал AutoHarness — набор инструкций и скриптов, который заставляет CLI-агентов изучать задачу, находить навыки и референсы, фиксировать критерии качества и проходить независимую проверку. По наблюдениям автора, это повысило предсказуемость Claude Code и других агентов, но формального бенчмарка пока нет.

## Контекст
Автор ранее работал в авиации и переносит в работу с агентами принцип предварительной подготовки и проверки. AutoHarness вырос из неудачных попыток поручить Claude Code (Opus 5.5) нарисовать сцену из Blade Runner 2049 в SVG без внешних генераторов: агенты работали по памяти, не искали референсы и не замечали, что исправления ломают другие части результата.

## Главное
- Исходная задача — нарисовать сцену Blade Runner 2049 в SVG без внешних генераторов; агенты, по словам автора, не искали настоящий кадр и рисовали по памяти.
- AutoHarness разбивает задачу на области знаний и ищет для них скиллы или MCP-серверы из доверенных источников, например маркетплейса Anthropic.
- Скачанные скиллы проверяются во временной папке; среди примеров опасных действий — чтение ~/.ssh и команда curl | sh. Для недостаточно доверенных кандидатов требуется согласие пользователя.
- До первой попытки агент измеряет референс и создаёт бриф с критериями качества, дословными ограничениями пользователя и планом проверки.
- Для проверки SVG агент открывает его в браузере, делает скриншот, сравнивает его с оригиналом и сверяет композицию и цвета с замерами.
- За результат отвечает независимый критик. Он может выставить blocker, major, minor или none; визуальные версии получает вслепую как A и B.
- Одноразовый id помогает скрипту принять именно актуальный отзыв критика, а не старую оценку; при повторении проблемы три раунда исполнитель обязан сменить подход.
- Система состоит из инструкций и скрипта autoharness, который сверяет журнал шагов и блокирует дальнейшую работу при пропуске обязательного этапа.
- Автор сообщает о поддержке Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code и GigaCode; для простых задач предусмотрен облегчённый режим.
- Формальной оценки эффективности пока нет; код проекта: https://github.com/D-Shey/autoharness.

## Как сделано
Перед выполнением агент разбивает задачу на области знаний и ищет для каждой подходящие скиллы или MCP-серверы в доверенных источниках. Кандидаты скачиваются во временную папку и проверяются на опасные действия, например чтение ~/.ssh или использование curl | sh; сомнительные скиллы требуют согласия пользователя. Если подходящего навыка нет, агент создаёт его сам. После задачи установленные скиллы удаляются.

Затем агент получает референс, измеряет важные параметры и записывает бриф: критерии хорошего результата, ограничения пользователя дословно и способ проверки. Для SVG он открывает файл в браузере, делает скриншот и сопоставляет его с оригиналом и предварительными замерами. Изменять файлы до создания брифа запрещает хук.

Результат проверяет отдельный агент-критик, который не участвовал в создании. Для визуального сравнения он получает варианты A и B без указания, какой из них новый. Отзыв содержит одноразовый id и оценку blocker, major, minor или none; скрипт проверяет id и сам извлекает оценку из сохранённого отзыва. Если проблема повторяется три раунда, исполнитель должен сменить подход. Если критик выявляет серьёзный дефект, агент сначала выясняет правило и добавляет его в скилл, а затем исправляет результат.

AutoHarness сочетает инструкции с запускаемым из терминала скриптом autoharness. Агент записывает шаги в журнал, а скрипт сверяет выполнение требований с журналом и не позволяет перейти дальше, если обязательный шаг пропущен. Созданные скиллы также можно тестировать: два агента решают задачи со скиллом и без него, а судья сравнивает результаты вслепую. Для простых задач предусмотрен облегчённый режим без поиска и брифа.

## Результаты
На задачах автора Claude Code с Opus 5.5 и AutoHarness, по его субъективной оценке, заметно лучше справлялся, особенно с визуальными заданиями; выполнение стало предсказуемее. Официального бенчмарка и количественных результатов нет. Автор сообщает, что независимый критик при проверке исправлений безопасности самого AutoHarness обнаружил два обхода хука и затем ещё три серьёзные проблемы, тогда как писавший код агент пять раз оценивал их как minor.

## Ограничения
Эффект AutoHarness пока основан на личных наблюдениях: автор не провёл формальный бенчмарк, поскольку полноценные прогоны дороги и требуют времени. Подготовка расходует дополнительные время и токены, поэтому система может быть избыточна для мелких задач. В статье не приведены сравнительные числа, стоимость прогонов или подробные результаты тестирования навыков.

## Что взять себе
- Для визуальных задач задавайте агенту проверяемые критерии и обеспечивайте доступ к референсу, а не полагайтесь на описание по памяти.
- Разделяйте создание и оценку: независимый критик может заметить проблемы, которые исполнитель недооценивает.
- Критичные требования лучше подкреплять скриптовыми проверками и журналом шагов, а не оставлять только в промпте.
- Учитывайте накладные расходы: поиск, бриф и проверки полезны для сложных задач, но для мелких автор предлагает облегчённый режим.

Агент создаёт бриф с критериями, ограничениями и планом проверки. Затем делает работу, визуально сопоставляет результат с референсом и получает оценку отдельного агента-критика. ## knowledge-v3:gpt-6.1-sol

## Коротко
AutoHarness добавляет к работе ИИ-агентов обязательную подготовку и независимую проверку. Это может помочь пользователям сложных задач получать более предсказуемые результаты, но преимущество пока не подтверждено полноценными тестами.

## Термины
- Скилл — набор инструкций для выполнения определённого типа задач.
- MCP-сервер — подключение, дающее агенту доступ к дополнительным инструментам и данным.
- Хук — программная проверка, которая может запретить агенту действие.
- Референс — исходный образец, с которым сравнивают результат.

## Контекст
Автор, ранее работавший в авиации, попросил Claude Code (Opus 5.5) нарисовать сцену из «Бегущего по лезвию 2049» в SVG без внешних генераторов. Испробованные агенты рисовали по памяти, не изучали кадр и при доработках портили уже сделанное. Из попытки закрепить обязательные вопросы и проверки вырос AutoHarness.

## Главное
- Перед выполнением задачи агент изучает нужные области знаний, подбирает инструкции и находит образец для сравнения.
- Критерии качества, условия пользователя и способ проверки фиксируются в коротком брифе до начала изменений.
- Результат оценивает другой агент; при сравнении изображений он не знает, какая версия новая.
- Соблюдение процесса проверяет программа, а не только текстовые указания: пропущенный шаг блокирует продолжение.
- Скачанные инструкции проверяются на опасные действия, а недостаточно доверенные требуют разрешения пользователя.
- Если одна проблема сохраняется три раунда, агент должен изменить подход.

## Как сделано
Агент подбирает или создаёт скиллы, изучает референс и составляет бриф. В Claude Code хук запрещает создавать и менять файлы до готовности брифа. Для SVG агент открывает результат в браузере, делает скриншот и сравнивает его с исходным кадром. Независимый критик выдаёт оценку blocker, major, minor или none. Скрипт autoharness проверяет журнал шагов и одноразовый id отзыва, чтобы не принять старую проверку за новую.

## Результаты
При исправлении безопасности AutoHarness основной агент пять раз подряд оценивал свою работу как minor. Независимый критик в первом раунде обнаружил два обхода хука, затем — ещё три серьёзные проблемы. Автор сообщает о заметном улучшении работы Opus 5.5, особенно с изображениями, но количественного сравнения качества не приводит. Заявлена поддержка Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code и GigaCode.

## Ограничения
Полноценного сравнительного тестирования пока нет: вывод об улучшении основан на личных задачах и впечатлениях автора. Подготовка требует дополнительного времени и токенов. Созданные агентом скиллы тоже могут содержать ошибочные рекомендации; автор предлагает проверять их на задачах со скиллом и без него.

## Что взять себе
- Для сложной задачи заранее задавайте образец, критерии приёмки и способ проверки результата.
- Визуальную работу проверяйте как изображение, а не только как код.
