# Message 2494

Источник: https://habr.com/ru/articles/1098004

## knowledge-v2:gpt-6-luna

## Коротко
Автор создал AutoHarness — набор инструкций и проверок, который заставляет CLI-агентов изучать задачу, находить навыки и референсы, а затем проверять результат независимой критикой. По словам автора, Claude Code с этим подходом справляется заметно лучше, особенно с визуальными задачами, но формального бенчмарка пока нет.

## Контекст
Автор ранее работал в авиации и перенёс в работу с агентами принцип предварительной подготовки и проверки по правилам. Идея AutoHarness возникла после неудачных попыток поручить Claude Code и другим агентам нарисовать SVG-сцену из Blade Runner 2049: они работали по памяти, не сверялись с кадром и объявляли задачу выполненной.

## Главное
- Исходная задача — нарисовать SVG-сцену из Blade Runner 2049 без внешних SVG-генераторов; агенты, по наблюдению автора, не искали референс и рисовали по памяти.
- Перед работой агент делит задачу на области знаний и ищет подходящие навыки или MCP-серверы в доверенных источниках, например в маркетплейсе Anthropic.
- Навыки проверяются перед установкой: учитывается доверие к источнику, а опасные действия вроде доступа к `~/.ssh` или `curl | sh` рассматриваются отдельно.
- Бриф фиксирует критерии хорошего результата, точные ограничения пользователя и способ проверки; без него хук запрещает агенту создавать или менять файлы.
- Для визуальной проверки SVG открывают в браузере, снимают скриншот и сопоставляют его с оригинальным кадром и заранее измеренными пропорциями, расположением объектов и цветом.
- Отдельный критик оценивает работу по шкале `blocker`, `major`, `minor`, `none`; для изображений сравнение проходит вслепую, без указания, какая версия новая.
- Одноразовый ID связывает отзыв с конкретной проверкой; программа сама считывает оценку, чтобы агент-исполнитель не пересказал и не смягчил критику.
- Повторяющаяся три раунда проблема требует сменить подход; серьёзную проблему сначала изучают и фиксируют в навыке, и только затем исправляют.
- Скрипт `autoharness` сверяет шаги с журналом задачи и блокирует продолжение, если обязательный этап пропущен; навыки также предлагается сравнивать на тестах со навыком и без него.
- Автор заявляет поддержку Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code и GigaCode.

## Как сделано
Перед выполнением агент разбивает задачу на области знаний, ищет подходящие навыки или MCP-серверы в доверенных источниках и при необходимости создаёт навык сам. Загружаемые навыки сначала помещаются во временную папку и проверяются на опасные действия, например чтение `~/.ssh` или запуск `curl | sh`; сомнительные требуют подтверждения пользователя, а временно установленные удаляются после задачи.

Затем агент получает референс и измеряет значимые параметры. Он составляет бриф с критериями качества, дословными ограничениями пользователя и планом проверки. Для SVG агент открывает файл в браузере, делает скриншот и сравнивает его с оригиналом и предварительными замерами. Пока бриф не подготовлен, хук блокирует создание и изменение файлов.

Результат проверяет отдельный агент-критик, который не участвовал в создании работы. Для изображений сравнение проводится вслепую. Критик выдаёт оценку `blocker`, `major`, `minor` или `none`; одноразовый ID проверки позволяет программе связать отзыв с нужным раундом и прочитать оценку из исходного файла. При серьёзной проблеме агент сначала уточняет правила и добавляет их в навык, а затем исправляет работу. Если проблема повторяется три раунда, он должен поменять подход.

AutoHarness сочетает инструкции для агента с запускаемым в терминале скриптом `autoharness`: тот сверяет записи в журнале с требуемыми шагами и не даёт продолжить, если они пропущены. Созданные навыки можно отдельно проверять на тестовых задачах: два агента выполняют их со навыком и без него, а судья сравнивает результаты вслепую.

## Результаты
Автор сообщает, что Opus 5.5 с AutoHarness заметно лучше справлялся с его задачами, особенно визуальными, а результаты стали предсказуемее. Количественных метрик и честного бенчмарка нет. Подготовка требует дополнительных времени и токенов; для простых задач вроде исправления опечатки предусмотрен облегчённый режим. Заявлена совместимость с Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code и GigaCode.

## Ограничения
Выводы основаны на личных задачах автора и впечатлениях; формального сравнения или опубликованных численных результатов пока нет. Полноценный прогон, по словам автора, дорог и занимает время, а подготовительная стадия увеличивает расход токенов. Оценки безопасности навыков и качества критики в статье не подкреплены независимым исследованием.

## Что взять себе
- Для сложной задачи полезно заранее определить референсы, измеримые критерии приёмки и способ увидеть результат, а не полагаться на самооценку агента.
- Независимая проверка важна: агент, создавший работу, может недооценить серьёзность собственных ошибок.
- Повторяемые процедуры лучше закреплять не только в промпте, но и в проверках, которые не дают пропустить обязательные шаги.
- Подготовку и проверку стоит соотносить с ценой ошибки: для небольших правок автор предлагает облегчённый режим без полного процесса.

## knowledge-v3:gpt-6-luna

## Коротко
Автор предлагает AutoHarness для Claude Code и других CLI-агентов: он заставляет их сначала изучить задачу, подготовить план и сверять результат с независимой оценкой. Это может помочь получать более последовательные результаты, особенно в сложных задачах, но эффективность пока не подтверждена формальным тестированием.

## Термины
- SVG — формат изображения, в котором рисунок задаётся кодом и геометрическими фигурами.
- MCP-сервер — подключаемый инструмент, который расширяет возможности AI-агента.
- Хук — автоматическое правило, которое запускается при определённом действии и может его разрешить или запретить.

## Контекст
Автор, ранее работавший в авиации, заметил, что агенты при создании SVG-сцены из Blade Runner 2049 не искали референсы и не проверяли рисунок, а после исправлений могли ухудшать другие части. Он перенёс в AutoHarness идею предварительной подготовки и проверок, знакомую ему по авиационной работе.

## Главное
- AutoHarness заставляет агента до начала работы определить, какие знания и инструменты нужны, и зафиксировать критерии результата.
- Агент проверяет свою работу по референсу, а отдельный критик оценивает её независимо; при серьёзной проблеме сначала уточняются правила, затем вносятся исправления.
- Скрипт проверяет, были ли выполнены обязательные шаги, а для мелких задач можно отключить часть подготовки.
- Автор поддерживает Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code и GigaCode.

## Как сделано
Перед изменением файлов агент разбивает задачу на области знаний, ищет подходящие скиллы или MCP-серверы в доверенных источниках и проверяет кандидатов на опасные действия. Если подходящего скилла нет, агент может создать его. Затем агент получает референс, фиксирует измеримые признаки хорошего результата и записывает бриф. Результат проверяется через просмотр, сравнение с референсом и отдельного агента-критика. Скрипт autoharness сверяет шаги с журналом и блокирует работу, если обязательный шаг пропущен. В конце временно установленные компоненты удаляются.

## Результаты
Автор сообщает, что Opus 5.5 с AutoHarness справлялся заметно лучше на его задачах, особенно визуальных. По его ощущениям, выполнение стало предсказуемее. Формального бенчмарка нет.

## Ограничения
Результаты основаны на опыте автора, а не на формальном сравнительном тесте. Подготовка занимает время и расходует токены, поэтому для мелких задач предусмотрен лёгкий режим без поиска и брифа. Проверка и настройка доверия к сторонним скиллам также требуют внимания.

## Что взять себе
- Для сложной задачи заранее укажите, с чем сравнивать результат и по каким признакам считать его хорошим.
- Не полагайтесь только на самооценку агента: независимая проверка может обнаружить пропущенные проблемы.
- Подготовка полезнее в сложных задачах; для простых исправлений её дополнительные затраты могут быть не оправданы.
- Относитесь к заявленному улучшению как к предварительному опыту автора, а не доказанному преимуществу.

## knowledge-v3:gpt-6.1-sol

## Коротко
AutoHarness добавляет к работе AI-агента обязательную подготовку, проверку по образцу и независимую критику. Это может помочь пользователям CLI-агентов получать более предсказуемые результаты, но улучшение пока подтверждено только опытом автора.

## Контекст
Автор раньше работал в авиации. Попросив Claude Code (Opus 5.5) нарисовать сцену из «Бегущего по лезвию 2049» кодом SVG без внешних генераторов, он обнаружил, что агенты не изучают настоящий кадр и объявляют работу готовой без сравнения. Повторяющиеся подсказки о подготовке и проверке он оформил в AutoHarness.

## Главное
- До выполнения задачи агент должен собрать нужные знания, найти образец и записать критерии хорошего результата.
- Обязательные этапы контролируются не только инструкциями: скрипт сверяет действия с журналом, а в Claude Code хук запрещает менять файлы до появления брифа.
- Результат оценивает отдельный агент. При сравнении изображений он не знает, какая версия новая.
- Проверка сторонних скиллов и запрос разрешения на сомнительные установки встроены в подготовку.
- AutoHarness работает с Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code и GigaCode.

## Как сделано
Агент разбивает задачу на области знаний, ищет и проверяет скиллы либо пишет недостающие сам. Затем изучает образец и составляет бриф с критериями, дословными условиями пользователя и способом проверки. Скрипт autoharness контролирует этапы по журналу. Независимый критик выдаёт оценку blocker, major, minor или none; одноразовый id защищает от подмены нового отзыва старым. Если проблема сохраняется три раунда, агент должен сменить подход.

## Результаты
При исправлении безопасности AutoHarness автор правок пять раз подряд оценивал свою работу как minor. Независимый критик сразу нашёл два способа обхода хука, а затем ещё три серьёзные проблемы. На собственных задачах автор заметил улучшение с Opus 5.5, особенно при работе с изображениями.

## Ограничения
Формального сравнительного тестирования пока нет: автор считает его дорогим и долгим. Подготовка расходует дополнительное время и токены. Проверка скачанных скиллов не означает полного доверия к ним; сомнительные установки требуют согласия пользователя. Скиллы, написанные самим агентом, тоже могут содержать неверные указания.

## Что взять себе
- Для сложной задачи заранее задавайте образец, критерии приёмки и способ проверки результата.
- Поручайте проверку другому агенту, а не полагайтесь на самооценку исполнителя.
- Для изображений проверяйте отрисованный результат, а не только исходный код.
- Для мелких исправлений используйте предусмотренный лёгкий режим без поиска и брифа.
