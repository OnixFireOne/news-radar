# Message 2494

Источник: https://habr.com/ru/articles/1098004

## knowledge-v2:gpt-6-luna

## Коротко
Автор создал AutoHarness — набор процедур и проверок для Claude Code и других CLI-агентов, чтобы те не начинали работу вслепую и не принимали собственные ошибки за успех. На его задачах, особенно визуальных, результаты с системой выглядели лучше, но формального бенчмарка пока нет.

## Контекст
Автор, ранее работавший в авиации, хотел перенести в работу CLI-агентов привычный для инженерных дисциплин порядок: изучить документацию, определить критерии качества и проверять результат. Поводом стала задача нарисовать SVG-сцену по мотивам Blade Runner 2049 без внешних генераторов: испробованные агенты не искали настоящий референс, рисовали по памяти и сообщали о готовности.

## Главное
- Тестовая задача — нарисовать SVG-сцену из Blade Runner 2049 без внешних генераторов; прежние агенты, по словам автора, обходились знаниями из памяти и не искали кадр.
- Система разбивает задачу на области знаний и ищет под них скиллы или MCP-серверы в доверенных источниках, например в маркетплейсе Anthropic.
- Скиллы проверяются перед установкой: среди опасных признаков названы чтение ~/.ssh и команда curl | sh; для неполностью доверенных вариантов нужно разрешение пользователя.
- До работы агент измеряет референс и формирует бриф из критериев качества, точных ограничений пользователя и плана проверки.
- Для визуального контроля SVG рендерится в браузере, снимок ставится рядом с исходным кадром и сверяется с замерами.
- Отдельный критик оценивает работу вслепую; возможные категории — blocker, major, minor и none.
- Проверку связывают с текущим раундом одноразовым ID; скрипт сверяет отзыв и журнал шагов, а хук не даёт редактировать файлы без брифа.
- При повторении проблемы три раунда агент должен изменить подход; созданные для задачи скиллы можно проверять на тестах с агентом без скилла и слепым судьёй.
- Автор заявляет поддержку Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Qwen Code и GigaCode; формального бенчмарка нет.

## Как сделано
Перед выполнением AutoHarness разбивает задачу на области знаний и ищет для каждой подходящие скиллы или MCP-серверы в доверенных источниках. Кандидаты получают оценку доверия, скачиваются во временную папку и проверяются на опасные операции, например чтение ~/.ssh или использование curl | sh; сомнительные варианты требуют согласия пользователя. Если подходящего скилла нет, агент создаёт его сам. Установленные компоненты удаляются после задачи.

Затем агент получает референс, фиксирует измеримые признаки результата и составляет бриф: критерии качества, исходные ограничения и способ проверки. Для SVG агент открывает файл в браузере, делает скриншот и сопоставляет его с оригиналом и предварительными замерами. Хук запрещает создавать или менять файлы, пока бриф не готов.

Результат проверяет отдельный агент-критик, который не участвовал в создании и не знает, какая из сравниваемых картинок новая. Оценка должна завершаться категорией blocker, major, minor или none. Одноразовый ID проверки и сохранение полного отзыва позволяют скрипту проверить, что оценка относится к текущему раунду. При серьёзном замечании агент сначала ищет правило и добавляет его в скилл; если одна проблема сохраняется три раунда, он должен сменить подход. Скрипт autoharness сверяет шаги с журналом и не разрешает продолжать, если обязательные действия не подтверждены.

## Результаты
Автор сообщает, что Opus 5.5 с AutoHarness на его задачах работал заметно лучше, чем без него, особенно при визуальной работе, а выполнение стало предсказуемее. В примере проверки безопасности независимый критик сразу выявил два способа обхода хука и затем ещё три серьёзные проблемы, тогда как автор исправлений пять раз подряд оценивал их как minor. Численных результатов бенчмарка автор не приводит.

## Ограничения
Сравнения не проверены формальным бенчмарком; выводы основаны на опыте автора. Полноценный прогон дорог и занимает время, а подготовка расходует дополнительные токены. Поэтому для мелких задач предусмотрен лёгкий режим без поиска и брифа. В статье не приведены количественные оценки качества, затрат или эффективности проверок.

## Что взять себе
- Для сложных задач заранее задавайте критерии приёмки и фиксируйте ограничения, а не полагайтесь на общий запрос и самооценку агента.
- Проверяйте артефакт в том виде, в котором его увидит пользователь: например, рендерите SVG, а не оценивайте только исходный код.
- Независимый критик и автоматические проверки шагов могут выявлять ошибки, которые создавший результат агент пропускает.
- Такая подготовка полезнее для сложной работы; для мелких правок дополнительные поиск, бриф и проверки могут быть неоправданны.
